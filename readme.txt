Задача
Вам нужно написать CLI-приложение (CLI — Command Line Interface), которое будет валидировать YAML-файл для конфигурации пода (Pod) в рамках инсталляции Kubernetes.
В качестве параметра приложение должно принимать путь до YAML-файла.

yamlvalid ./test.yaml 

Приложение должно считать содержимое файла и декодировать его. Используйте пакет  gopkg.in/yaml.v3.
Требования к конфигурации пода
Ниже представлены требования, которые мы предоставляем к конфигурации пода (Pod) в рамках инсталляции Kubernetes.
Обратите внимание, что среди требований есть как обязательные, так и необязательные поля.
1. Поля верхнего уровня
apiVersion (string) — определяет версию схемы формата. На данный момент используется только v1. Поле обязательно.
kind (string) — определяет сущность, которую описывает файл. Для описания пода валидным значением является Pod. Поле обязательно.
metadata (ObjectMeta) — описывает дополнительные данные о сущности пода. Формат объекта описан в разделе ObjectMeta. Поле обязательно.
spec (PodSpec) — описывает сущность пода. Формат объекта описан в разделе PodSpec. Поле обязательно.
2. ObjectMeta
name (string) — задаёт имя пода. Должно быть уникально в рамках одного неймспейса. Поле обязательно.
namespace (string) — задаёт неймспейс пода. Поле не обязательно.
labels (Object) — набор произвольных строковых пар «ключ-значение» для описания пода. Поле не обязательно.
3. PodSpec
os (PodOS) — описание требований к операционной системе пода. Формат объекта описан в разделе PodOS. Поле не обязательно.
containers (Container[]) — список объектов с описанием состояния контейнеров пода. Формат объекта описан в разделе Container. Поле обязательно.
4. PodOS
name (string) — задаёт имя операционной системы пода. Возможные значения: linux, windows. Поле обязательно.
5. Container
name (string) — задаёт имя контейнера в рамках пода. Должно быть уникально в рамках одного пода, формат — snake_case. Поле обязательно.
image (string) — задаёт имя и тег исходного образа контейнера. Адрес образа должен быть в домене registry.bigbrother.io, наличие тега версии обязательно. Поле обязательно.
ports (ContainerPort) — описывает открытые порты контейнера. Формат объекта описан в разделе ContainerPort. Поле не обязательно.
readinessProbe (Probe) — описывает стратегию периодической проверки готовности контейнера к работе. Формат объекта описан в разделе Probe. Поле не обязательно.
livenessProbe (Probe) — описывает стратегию периодической проверки контейнера на активность. Формат объекта описан в разделе Probe. Поле не обязательно.
resources (ResourceRequirements) — описывает требования к поду по доступным ресурсам. Формат объекта описан в разделе ResourceRequirements. Поле обязательно.
6. ContainerPort
containerPort (integer) — задаёт открытый порт контейнера. Должен быть валидным портом в пределах 0 < x < 65536. Поле обязательно.
protocol (string) — указывает сеть, на которой открыт порт. Возможные значения: TCP, UDP. По умолчанию: TCP. Поле не обязательно.
7. Probe
httpGet (HTTPGetAction) — описывает правила выполнения HTTP GET запроса к контейнеру. Поле обязательно.
8. HTTPGetAction
path (string) — путь, с которым будет выполнен HTTP GET запрос к контейнеру. Должен быть абсолютным путём. Поле обязательно.
port (integer) — порт, по которому будет выполнен HTTP GET запрос к контейнеру. Должен быть валидным портом в пределах 0 < x < 65536. Поле обязательно.
9. ResourceRequirements
requests (object) — минимальный объём ресурсов, необходимый контейнеру. Поле не обязательно.
limits (object) — максимальный объём ресурсов, необходимый контейнеру. Должен быть абсолютным путём. Поле не обязательно.
Доступные ресурсы для ResourceRequirements:

    cpu (integer) — ядро процессора,
    memory (string) — оперативная память в единицах степени двойки:Gi,Mi,Ki.

Данные требования являются надмножеством официального API Kubernetes. То есть предъявляются более жёсткие требования к YAML-файлу с описанием пода Kubernetes
